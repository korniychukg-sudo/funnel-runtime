# Работа с AI-агентами

Работу вёл оркестратор: основная сессия Claude Code. Он запускал субагентов волнами, сам писал контракты и общий движок, сам интегрировал результат. Правила работы:

- агенты одной волны работают с непересекающимися файлами и общим контрактом;
- результат агента принимается только после запуска: тестов, генератора, браузера, а не со слов агента;
- находки ревью проходят состязательную проверку перед исправлением.

Все времена — 2026-10-02, МСК. Сводный таймлайн — в [`README.md`](../README.md#таймлайн).

## 4. Интеграция: оркестратор (до 16:39)

- Сборка частей, полный прогон `npm test` и `npm run typecheck`.
- **Дефект движка, найденный тестом агента.** Тест на синтетическом конфиге проверял цепочку условий: `bike_storage` зависит от `bike_type`, а тот — от `transport`. Тест показал, что `progressFor` продолжал считать зависимый шаг, когда шаг-источник скрыт: условие оставалось «неизвестным», и в счётчике «Question N of M» висел лишний вопрос. Исправление: ответы скрытых шагов считаются заведомо отсутствующими (тест «drops a chained conditional step whose source step is hidden» в [`tests/engine.test.ts`](../tests/engine.test.ts)). В выданных v1 и v3 цепочек условий нет, поэтому дефект поймался только благодаря третьему, синтетическому конфигу.
- **Сквозной прогон.** Сервер, `npm run generate -- --scenario iteration2` и `npm run verify`: 165/165 проверок совпали с ground truth генератора.
- **Браузерная проверка** страниц `/`, `/admin` и `/dashboard`.
- Коммит `8c2f3ce`.

## 5. Ревью: пять направлений, у каждого состязательный верификатор (16:40–17:01)

| Направление | Что проверялось |
|---|---|
| соответствие заданию | каждое требование п. 1–9 по матрице требований |
| backend | транзакции, коды ошибок, закрепление версии, TTL, поведение при откате |
| аналитика и генератор | агрегаты против контракта, крайние случаи: нулевые знаменатели, Back, порядок, дубли; воспроизводимость генератора |
| клиент | состояние при refresh и Back, outbox, ошибки сети, доступность |
| безопасность и устойчивость | токен админки, лимиты тела, приватность ответов, валидация входа, зависимости, деплой |

На каждом направлении работали ревьюер и отдельный верификатор. Верификатор запускался, когда ревьюер своего направления заканчивал, и пытался опровергнуть каждую находку: воспроизвести её или показать, что это не дефект. Параллельно с ревью отдельный агент писал черновик документации (16:40–16:54).

Итог: **28 находок подтверждено, 12 опровергнуто**. Направления пересекаются, поэтому часть подтверждённых находок — одна и та же проблема: путь к БД нашли три направления, непроверенные значения свойств — тоже три.

Самые важные подтверждённые:

| Находка | Чем грозила |
|---|---|
| путь к БД по умолчанию `./data/funnel.db` относительно рабочего каталога, а не на томе Railway `/data` | каждый передеплой стирал бы версии, сессии и события |
| значения свойств событий не проверялись | под разрешёнными ключами можно было сохранить сырые ответы, персональные данные или строку почти в 1 МБ; подделать `result_id`; сессия, не ушедшая дальше интро, могла засчитаться как дошедшая до результата и кликнувшая CTA |
| при уходе со страницы outbox ничего не отправлял, пока обычная пачка была в полёте | ревьюер воспроизвёл это в headless Chrome с замедленным `POST /api/events`, верификатор — на настоящем `Outbox` через tsx: последние события (`result_viewed`, `cta_clicked`) терялись, и сессия с конверсией считалась отвалом на `tool_count` |
| генератор `--scenario iteration2` падал на базе, где v3 уже импортирована | импорт возвращал `409 version_exists`, а уже созданные сессии оставались только с `session_started` и портили dashboard без фильтра |

Остальные подтверждённые, коротко: счётчик «Question 6 of 7» на последнем вопросе v3 B; z-тест без минимальной выборки; нельзя выбрать сессии без кампании; `recommendation_expanded` не видно на dashboard; `@fastify/static` 8.3.0 с предупреждениями `npm audit`; SPA-fallback отдавал `index.html` с 200 на несуществующие файлы; ключ `__proto__` в одном событии ронял всю пачку с 400; проверки конфига не учитывали overrides варианта, а `ttlHours` не был ограничен; ответы можно было менять во время отправки; Back во время запроса терялся; истёкшая сессия при перезагрузке заменялась молча; вкладки затирали outbox друг друга; генератор ставил событиям время раньше создания сессии; `--seed` не делал прогон воспроизводимым; пробелы в README и неверная команда `verify` в контрактах; создание сессии не идемпотентно; у хука `useFunnelSession` нет автотестов.

Примеры опровергнутых: «у `session_started` нет клиентского времени», «админка открыта, если `ADMIN_TOKEN` не задан», «`/api/analytics` читает всю таблицу событий и тормозит воронку», «нет rate limiting».

Решение об исправлении принимал оркестратор, и только по подтверждённым находкам.

## 6. Исправления: 3 агента на непересекающихся файлах (17:01–17:15)

| Агент | Файлы | Что исправлено |
|---|---|---|
| сервер | `src/server/app.ts`, `index.ts`, `routes/events.ts`, `src/shared/config.ts`, `package.json` и их тесты | правило пути к БД и лог пути при старте; проверка значений свойств (`invalid_property`), `step_type` и `answer_kind` ставит сервер; вырезание `__proto__` вместо 400; проверки конфига по шагам после overrides, `ttlHours` ≤ 8760; SPA-fallback только для страниц; `@fastify/static` ^10.1.5 |
| аналитика | `src/server/analytics.ts`, `src/shared/api.ts`, страницы dashboard и их тесты | минимальная выборка для z-теста; фильтр `utm_campaign=(none)`; `DataQuality.events` и таблица Events by name |
| клиент | `src/client/outbox.ts`, `src/client/funnel/*` и их тесты | отправка при уходе со страницы во время пачки, keepalive до 60 000 байт; слияние очереди между вкладками; блокировка полей во время отправки; отложенный Back; уведомление об истёкшей сессии при перезагрузке; счётчик вопросов по редактируемому ответу; раскрытый результат сохраняется |

Генератор и `verify` в том же коммите поправил оркестратор: проверка v3 до старта `iteration2`, доставка событий начатых сессий при сбое, реальное время событий, сверка кампании `(none)`, честное описание `--seed`.

Каждый агент прогнал `tsc` и `vitest`. Серверный агент проверил маршруты на собранном сервере, клиентский — отложенный Back, блокировку полей и счётчик вопросов в браузере на отдельном локальном сервере. Итог у оркестратора: 12 файлов, 194 теста, `tsc` без ошибок. Коммит `17f36b7` (17:15).

Не исправлено:

- создание сессии не идемпотентно ([`README.md`](../README.md#допущения-и-известные-ограничения));
- для хука `useFunnelSession` по-прежнему нет DOM-тестов (нужна новая зависимость вроде jsdom); отложенный Back проверен только вручную в браузере;
- отдельного KPI для `recommendation_expanded` нет: для v1 он показывал бы ложный 0, поэтому событие видно в таблице событий по имени;
- CTA по-прежнему отправляет `cta_clicked` и `recommendation_expanded` одним кликом.

## 7. Хостинг

Требования: бесплатно, без привязки карты, постоянно работающий процесс Node и постоянный диск под SQLite. Внешняя БД не подходит: задание запрещает сторонние сервисы.

- Первый список кандидатов дал агент волны анализа. Отдельное исследование (16:21–16:38, 2 агента: Railway и остальные варианты) проверило условия по документации и тарифам.
- alwaysdata запросил карту, поэтому выбран Railway: trial на 30 дней без карты, затем Free plan; том до 0.5 ГБ переживает передеплой; домен `*.up.railway.app` не за Cloudflare.
- Риск, найденный исследованием: часть edge-адресов Railway не отвечала с российских узлов check-host.net (Москва, Санкт-Петербург). Поэтому доступность проверялась с российских узлов, а в ограничениях README записано, что она может зависеть от IP edge-узла.

## 8. Деплой и живая вторая итерация

- 17:04 — первый деплой на Railway: один сервис, Railpack по [`railway.json`](../railway.json), том 0.5 ГБ в `/data`, `DB_PATH=/data/funnel.db`, `ADMIN_TOKEN` сначала не был задан ([`README.md`](../README.md#деплой)). Финальная проверка глазами проверяющего (чистый клон по README и публичный стенд по п. 9 и 11) отметила, что при публичном репозитории открытая админка позволяет любому откатить версию или занять номер версии мусорным конфигом, поэтому в 18:02 админка закрыта токеном.
- ≈17:16 — передеплой `17f36b7`. База пережила его: запись `seed` из первого деплоя осталась в журнале активаций.
- 17:18–17:23 — вторая итерация на публичном URL: трафик v1 (83/83), две сессии v1 оставлены на середине, публикация v3 в `/admin`, новые сессии на v3, старые сессии завершены на v1, `recommendation_expanded` принят для v3 и отклонён для v1, трафик v3 (96/96), откат в `/admin`, после отката обе сверки снова 83/83 и 96/96. Сессии вёл скрипт через публичный HTTP API. Код, схема и деплой между публикацией и откатом не менялись. Пошагово: [`iteration-2.md`](iteration-2.md#ход-проверки-на-публичном-url).
